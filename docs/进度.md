### 已知限制：Windows 侧 DSH 的 shell 用不了

实测（2026-10-14）：调 `pwsh` 无论跑什么命令，都返回退出码
**`0xC0000142`**（`STATUS_DLL_INIT_FAILED`，进程还没执行到命令就挂了），
`echo hello` 也一样。

- **受影响**：`make sim` / `make lint` / `git push` 这类要开子进程的事，DSH 在这台机器上做不了
- **不受影响**：读文件、写文件、grep，全部正常
- **绕法**：需要命令行时，人自己开 **Git Bash** 或 **GitHub Desktop** 点按钮

## 装图形界面（看波形）

`make sim` 除了跑检查，还会把波形写到 `build/<tb名>.vcd`。
VCD 是文本格式，用肉眼看没意义，需要一个波形查看器。

**Homebrew 的现状**（2026-10 查证）：GTKWave 在 Homebrew 里已经
[被标记为 disabled](https://formulae.brew.sh/cask/gtkwave)，
上游也没有可用的 macOS 二进制（[gtkwave#390](https://github.com/gtkwave/gtkwave/issues/390)）。
所以现在装 **[Surfer](https://formulae.brew.sh/formula/surfer)**：Rust 写的，
原生窗口、Apple Silicon 有现成二进制、不需要 X11。

### 步骤

1. 装 Homebrew（先确认 Xcode 命令行工具已装：`xcode-select -p` 有输出就行）：

   ```sh
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   ```

2. Apple Silicon 上它装在 `/opt/homebrew`，装完要把它加进 PATH
   （安装脚本最后会打印这两行，照着敲也行）：

   ```sh
   echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
   eval "$(/opt/homebrew/bin/brew shellenv)"
   ```

3. 装波形查看器：

   ```sh
   brew install surfer
   ```

4. 之后看波形就一条命令（`make wave` 会自动优先用 Surfer，
   没装 Surfer 才退回 GTKWave）：

   ```sh
   make wave VCD=build/tb_blinky.vcd
   ```

   不带 `VCD=` 时只列出已经生成的波形文件。


## 已知坑（踩过的，别再踩）

### 1. iverilog 13.0：字符串常量赋给向量会损坏非 ASCII 字节

把含中文的字符串常量赋给 `reg [N:0]` / 向量，只有部分字节写得进去，
其余位留成 x，`$display("%s")` 打出来是一堆乱码。

对照实验（都实测过）：

| 写法 | 结果 |
|---|---|
| `$display("%s", "level 稳定为 0")` | ✅ 正常 |
| `reg [8*40-1:0] m; m = "level 稳定为 0";` | ❌ 乱码 |
| 同上，但字符串用八进制转义 `"\347\250\263…"` | ❌ 照样乱码 |
| `m[319-:8] = 8'hE7; …` 逐字节赋值 | ✅ 正常 |

**所以 `tb_common.vh` 里的 `check` / `check_eq` 是宏，不是 task** ——
宏是文本替换，中文会原样落在 `$display` 的参数位置上，不经过向量。

**代价：调用时要写反引号，而且断言必须单独成行**（宏里有 `if/else`，
写成 `if (x) \`check(...); else ...` 会 dangling else）：

```verilog
`check(cond, "描述文字");
`check_eq("描述文字", actual, expected);
```

### 2. `tb_errors` 由 `tb_common.vh` 声明，testbench 里不要再写一遍

Verilog 要求先声明后使用。`include` 展开在模块开头，所以
`integer tb_errors = 0;` 必须写在几个断言**之前**。放在头文件里最省事。

### 3. `sim.sh` 必须带 `-I $ROOT/tb`

`tb_common.vh` 在 `tb/`，而各 stage 的 testbench 在 `s0x_xxx/tb/`，
只加 `-I $TBDIR` 找不到。

### 4. bash 3.2 + UTF-8：`$VAR` 紧跟中文字符会吃掉字符

macOS 自带的 `/bin/sh` 是 **bash 3.2（2007 年）**。在 UTF-8 locale 下，
`$VAR` **紧挨着**一个中文字符时，bash 会把那个中文字的字节当成
变量名的一部分，于是变量值和半个字一起消失。

实测（`T=4`）：

| 写法 | 输出 | 结果 |
|---|---|---|
| `echo "x$T个"` | `x` + 半个"个" | ❌ 丢了 `4` |
| `echo "x${T}个"` | `x4个` | ✅ |
| `echo "x$T 个"`（有空格） | `x4 个` | ✅ |
| `LC_ALL=C` 下 `echo "x$T个"` | `x4个` | ✅ |

**规律：变量展开后面直接跟非 ASCII 字符就会出事**，跟空格就没问题。
因为 locale 是 UTF-8，实际环境里就会踩到。

**症状很隐蔽**：不报错、退出码 0，只是那行字少了一两个字符，
看起来像"终端渲染问题"，很容易当成显示 bug 放过去。

**规避：变量一律写 `${VAR}`**（花括号明确边界，任何 locale 都对）。
本仓库已按此修掉 `scripts/sim.sh` 的结果行和 `scripts/setup_tools.sh`
的两行提示。

排查方法：`命令 | hexdump -C` 看原始字节，别信终端渲染。

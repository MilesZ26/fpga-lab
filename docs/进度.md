## 已知坑（踩过的，别再踩）

### 1. iverilog 13.0：字符串常量赋给向量会损坏非 ASCII 字节

把含中文的字符串常量赋给 `reg [N:0]` / 向量，只有部分字节写得进去，
其余位留成 x，`$display("%s")` 打出来是一堆乱码。

对照实验（都实测过）：

| 写法 | 结果 |
|---|---|
| `$display("%s", "level 稳定为 0")` | ✅ 正常 |
| `reg [8*40-1:0] m; m = "level 稳定为 0";` | ❌ 乱码 |
| 同上，但字符串用八进制转义 `"\347\250\263…"` | ❌ 照样乱码 |
| `m[319-:8] = 8'hE7; …` 逐字节赋值 | ✅ 正常 |

**所以 `tb_common.vh` 里的 `check` / `check_eq` 是宏，不是 task** ——
宏是文本替换，中文会原样落在 `$display` 的参数位置上，不经过向量。

**代价：调用时要写反引号，而且断言必须单独成行**（宏里有 `if/else`，
写成 `if (x) \`check(...); else ...` 会 dangling else）：

```verilog
`check(cond, "描述文字");
`check_eq("描述文字", actual, expected);
```

### 2. `$readmemh` 读不到文件时**不报错**，表里全是 x

`$readmemh` 的路径是相对**仿真/综合进程的工作目录**，不是相对 `.v` 文件所在目录。
`sim.sh` 里 `vvp` 是在 `build/` 里跑的，所以 RTL 里写 `"s01_nco/lut/sin.mem"`
这种相对路径**必然读不到** —— 而且不报错、不警告，ROM 里全是 x，波形一片红。

规避：`scripts/sim.sh` 会自动传宏 `LUTDIR`（绝对路径），RTL / TB 统一写成

```verilog
`ifndef LUTDIR
  `define LUTDIR "s01_nco/lut/"     // 兜底：手工跑 iverilog / Vivado 综合
`endif
initial $readmemh({`LUTDIR, "sin.mem"}, sin_rom);
```

细节见 `s01_nco/lut/README.md`。

### 3. `tb_errors` 由 `tb_common.vh` 声明，testbench 里不要再写一遍

Verilog 要求先声明后使用。`include` 展开在模块开头，所以
`integer tb_errors = 0;` 必须写在几个断言**之前**。放在头文件里最省事。

### 4. `sim.sh` 必须带 `-I $ROOT/tb`

`tb_common.vh` 在 `tb/`，而各 stage 的 testbench 在 `s0x_xxx/tb/`，
只加 `-I $TBDIR` 找不到。

### 5. bash 3.2 + UTF-8：`$VAR` 紧跟中文字符会吃掉字符

macOS 自带的 `/bin/sh` 是 **bash 3.2（2007 年）**。在 UTF-8 locale 下，
`$VAR` **紧挨着**一个中文字符时，bash 会把那个中文字的字节当成
变量名的一部分，于是变量值和半个字一起消失。

实测（`T=4`）：

| 写法 | 输出 | 结果 |
|---|---|---|
| `echo "x$T个"` | `x` + 半个"个" | ❌ 丢了 `4` |
| `echo "x${T}个"` | `x4个` | ✅ |
| `echo "x$T 个"`（有空格） | `x4 个` | ✅ |
| `LC_ALL=C` 下 `echo "x$T个"` | `x4个` | ✅ |

**规律：变量展开后面直接跟非 ASCII 字符就会出事**，跟空格就没问题。

**症状很隐蔽**：不报错、退出码 0，只是那行字少了一两个字符，
看起来像"终端渲染问题"，很容易当成显示 bug 放过去。

**规避：变量一律写 `${VAR}`**（花括号明确边界，任何 locale 都对）。

排查方法：`命令 | hexdump -C` 看原始字节，别信终端渲染。

### 6. 每个 RTL 文件都要写 `` `timescale ``

少写一个，iverilog 会**从上一个编译的文件那里继承**过来，于是：

- `make lint` 打出 `timescale for nco inherited from another file`（编译顺序一变就变）；
- 单文件仿真时打 `Some modules have no timescale ...`。

现在 5 个 RTL 文件全部写了 `` `timescale 1ns/1ps ``，警告消失。
TB 里的断言和 `#延时` 都依赖 timescale，继承来的值不可控，所以这条不是洁癖。

### 7. 纯参数的计算不能放在 `always @(*)` 里（敏感列表是空的）

写 `always @(*) temp = FREQ_HZ << PHASE_W;`（右边全是 `parameter`）时，
**块里没有任何信号可敏感，iverilog 从头到尾不执行它** —— `temp` 一直是 `x`，
而且不报错。实测：`always @(*)` 版本 `temp=x`，改成 `localparam` 立刻算出正常值。

顺带把那句最容易传错的位宽规则说清楚（两种写法都实测过）：

| 写法 | 结果 | 原因 |
|---|---|---|
| `localparam integer X = FREQ_HZ << PHASE_W;`（32 位目标） | `1<<32` → **0** | 移位左操作数按上下文宽度 = 32 位 |
| `localparam [63:0] X = FREQ_HZ << PHASE_W;`（64 位目标） | `1<<32` → 4294967296 ✅ | 赋值目标的宽度会**反过来**加宽表达式 |

所以"左操作数不会因为右边是 64 位就被加宽"是**错的**：位数由**上下文**（赋值目标）决定。
真要稳，就直接写 `64'd1 << PHASE_W`，别依赖上下文推断。

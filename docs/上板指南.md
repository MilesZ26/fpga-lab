# 上板指南 — 从零到 LED 闪烁（Windows / Vivado）

> 目标：把 `s00_blinky` 真正跑到板子上，走通
> **原理图 → XDC → 综合 → 实现 → 比特流 → 下载** 这条链路。
>
> 走通一次之后，后面每个 stage 都照这个流程下板。
>
> ⚠️ 本文里的**引脚号、时钟频率、器件封装**一律是占位符。
> 这些只能从板子的**原理图**（或厂商例程自带的 `.xdc`）里抄，
> **不要靠搜索或记忆猜** —— 引脚错了就是上板不亮，而且很难查。

---

## 开始之前：确认 Vivado 版本可用

**这个仓库对 Vivado 版本几乎没有要求。** 因为我们**从不打开厂商的教程工程**——
RTL 全是手写的，没有 IP 核、没有 Block Design；引脚号是从**原理图**上抄的纯文本，
跟教程用的 `.xpr` 一点关系都没有。

> 教程用的是 2020.2，这只在**你去打开教程工程**时才绑住你。我们不打开。

真正有影响的只有两件事：

1. **操作系统支持**。2020.2 发布时 Windows 11 还不存在，官方支持目标是 Win10；
   新版本才正式支持 Win11。权威来源是 AMD 的
   [Installer and OS Support Information](https://www.amd.com/en/support/adaptive-socs-and-fpgas/installer-info-general.html)
   （这个页面是 JS 渲染的，得用浏览器打开）。
2. **器件是否还在支持列表里**。Artix-7 属于 7 series，到 2025.x 仍在支持范围内，
   免费版也覆盖。

### 选版本的三个原则

**① 认准免费版**：选 **Vivado ML Standard Edition**（原来叫 WebPACK）。
Artix-7 在免费范围内，**不需要 License 文件**。别选 Enterprise。

**② 不要追最新**。新版本的更新几乎全是给 Versal 等新架构的，
对一棵 Artix-7 的闪灯设计收益为零，却要承担新版本的 bug 风险——
而新手最怕的正是分不清"我操作错了"和"工具出 bug 了"。
选一个**已经出了半年以上、且官方支持你系统**的版本更稳。

**③ ⚠️ 安装时务必勾上 `7 series` / `Artix-7`。**
新版安装器会让你勾选器件族。漏勾的话装完在 Parts 里搜不到 `xc7a100t`——
社区里就有 [2025.2 只装了 Spartan-7、看不到 Artix-7](https://adaptivesupport.amd.com/s/question/0D5Pd00001MlsTLKAZ/hello-i-have-downloaded-vivado-20252-for-linux-with-support-for-7series-after-installation-in-ubuntu-24-vivado-can-see-only-spartan7-devices-and-no-artix7-devices-the-old-vivado-20212-can-see-artix-7?language=en_US) 的实例。

> 只勾需要的器件族还能**大幅减小安装体积**。全量安装是几十 GB 下载、
> 上百 GB 磁盘；只装 7 series 会小很多。

### 装完第一件事：自检器件

打开 Vivado，在底部的 **Tcl Console** 里敲：

```tcl
get_parts xc7a100t*
```

- 返回一串器件名 → ✅ 器件族装好了
- 报错或返回空 → ❌ 回去用 installer 补装 `7 series`

**这一条必须在建工程之前做掉**，否则你会在"Create Project 里搜不到自己的芯片"
上卡半天，还以为是板子或工程的问题。

## 第 0 步：从原理图抄 5 个数（唯一需要"查资料"的一步）

打开正点原子达芬奇 Pro 的原理图 PDF，按下表搜网络标号。
找不到就翻用户手册的"管脚分配"章节（正点原子文档通常带这么一张表）。

| # | 要什么 | 在原理图里搜 | 记成 |
|---|---|---|---|
| 1 | FPGA 完整型号 | 板子丝印 / 原理图首页 | `xc7a100t` + 封装 + 速度等级 + 温度等级，例：`xc7a100tfgg484-2` |
| 2 | 主时钟引脚 | `CLK` / `OSC` / `SYS_CLK` / `50M` / `100M` | 形如 `Y18` |
| 3 | 该时钟的频率 | 同上，或晶振丝印 | 50 MHz / 100 MHz … |
| 4 | LED 引脚 | `LED` / `LED0` / `DS0` | 形如 `M14` |
| 5 | 复位按键引脚 | `KEY` / `RST` / `KEY0` / `S1` | 形如 `N15` |

### 顺手记下另外两件事（不记也能跑，但迟早要用）

- **LED 的极性**：原理图里 LED 是"FPGA 引脚 → 电阻 → LED → GND"（**高电平点亮**），
  还是"VCC → 电阻 → LED → FPGA 引脚"（**低电平点亮**）。看二极管方向。
- **按键的极性**：按下时把引脚拉到 GND（**低有效**，`0` = 按下）
  还是拉到 VCC（**高有效**）。

> ⚠️ **器件封装（第 1 项）最容易出错也最致命**。
> 同为 XC7A100T，`fgg484` 和 `csg324` 的引脚编号完全不同。
> 型号选错 → 引脚约束全部对不上 → 要么报错，要么"下载成功但灯不亮"。
> 从 Vivado 的 Parts 列表里挑**完全一致**的那一项。

## 第 1 步：建 Vivado 工程

**工程目录必须建在仓库外面。**

```
D:\vivado_prj\s00_blinky\     ← 工程建这里
D:\fpga-lab\                  ← git 仓库在这里
```

为什么要这样：Vivado 的中间文件动辄几 GB 且每次综合都在变。
工程建在仓库里，`git add -A` 一不留神就把几 GB 扫进去了，
而**已经提交过的东西 `.gitignore` 再也管不住**。
建在外面，git 在物理上就看不到它。
（详见 [同步指南.md](同步指南.md) 的「坑 2」）

### 操作

1. Vivado → **Create Project**
2. **Project Name**
   - Project name: `s00_blinky`
   - Project location: `D:/vivado_prj` ← **仓库外**
   - ✅ 勾上 Create project subdirectory
3. **Project Type** → 选 **RTL Project**
   - ❌ **不要**勾 "Do not specify sources at this time"
4. **Add Sources**
   - Add Files → `D:\fpga-lab\s00_blinky\rtl\blinky.v`
   - ❌ **不要**勾 "Copy sources into project"
   - ✅ 勾 "Scan and add RTL include files"
5. **Add Constraints**
   - Add Files → `D:\fpga-lab\s00_blinky\constr\blinky.xdc`
   - ❌ **不要**勾 "Copy constraints files into project"
6. **Default Part**
   - 搜 `xc7a100t`，选**和第 0 步完全一致**的封装/速度/温度等级
7. Finish

> **"不要勾 Copy sources into project" 的理由**：
> 勾了 Vivado 会把源文件**复制一份**到工程目录里。
> 之后你在仓库里改 RTL、重新综合 —— 综合的还是那份旧的副本，
> 于是出现"改了代码但不生效"的诡异现象，能查半天。
> 不勾 = 工程直接引用仓库里的文件，改完立刻生效。

## 第 2 步：填 XDC 约束

打开仓库里的 `s00_blinky/constr/blinky.xdc`，把三个 `TODO` 块填掉、
取消注释。要用第 0 步抄来的数。

因为工程是**按路径引用**这个文件的，改完**不需要**在 Vivado 里
重新添加约束，直接重新 Run Synthesis 就生效。

### 关于 `CLK_HZ` 参数

`blinky.v` 里 `CLK_HZ` 的默认值是 `50_000_000`。
如果你的板载时钟不是 50 MHz，把它改成实际值，然后 `git commit`。

**为什么直接改源码而不是在 Vivado 里改**：改源码会进 git，有记录、
可复现、我这边能看见；在 Vivado 界面里改只存在工程文件里，
换台机器就丢，而且出问题时无从对照。

（Tcl 方式也行：`synth_design -generic CLK_HZ=50000000`。
GUI 流程下改源码更省事。）

## 第 3 步：综合

- **Run Synthesis**（左侧 Flow Navigator）
- 等它跑完，看打开的 Synthesis Design 有没有问题
- 结束时会弹窗，选 **Open Synthesized Design**

**要看的**：Tcl Console 里的 `CRITICAL WARNING`。最常见的是**端口名对不上**：

| 现象（消息文本） | 含义 |
|---|---|
| `'set_property' expects at least one object` | XDC 里 `get_ports xxx` 没匹配到任何端口 |
| 提到 `No ports matched` / `get_ports` 找不到对象 | XDC 里的端口名和 RTL 里的不一致 |

> 这类错误的根因几乎总是同一个：`get_ports` 后面写的名字
> 必须是**顶层模块的端口名**（这里是 `clk` / `rst_n` / `led`），
> 不是网络标号、不是引脚号。
>
> （具体错误码随 Vivado 版本会变，按**消息文本**搜，别按错误码搜。）

---

## 第 4 步：实现 + 生成比特流

- **Run Implementation** → **Open Implemented Design**
- 看 **Timing Summary**：`WNS`（Worst Negative Slack）必须 **≥ 0**
- **Generate Bitstream**

> `s00_blinky` 是纯粹的分频计数器，时序**不可能**不收敛。
> 如果这里出现违例，一定是约束填错了（多半是 `create_clock` 周期写反了），
> 不要去找 RTL 的问题。

---

## 第 5 步：下载

1. 板子**上电**，USB 线接下载口
2. Flow Navigator → **Open Hardware Manager**
3. **Open Target** → **Auto Connect**
4. 出现 `xc7a100t_0` 之类的器件图标 = 识别成功
5. 右键器件 → **Program Device** → 选刚生成的 `.bit`
6. **Program**

下载完成后应该看到 LED 以设定频率闪烁。

> ⚠️ **掉电即失**：这是 SRAM 配置方式，断电后 FPGA 就变回空白。
> 每次上电都要重新下载。想让上电自动跑，需要把比特流烧进配置 Flash
> （那是另一件事，s00 不需要）。

## 排障：灯不闪怎么办

按**从后往前**的顺序二分，别跳步。

### ① 先确认比特流真的下进去了

- Hardware Manager 里器件有没有出现？没有 → 见下面「识别不到器件」
- Program 之后有没有报错？
- 板子上有没有 `DONE` 指示灯亮？亮了至少说明配置成功

### ② 用"常亮/常灭"排除引脚和极性（**最有效的一招**）

把 `blinky.v` 里最后一行的

```verilog
assign led = led_r;
```

临时改成

```verilog
assign led = 1'b1;    // 低电平点亮的板子改成 1'b0
```

重新综合下载：

| 结果 | 结论 |
|---|---|
| **亮了** | 引脚对、下载链路对 → 问题在**闪烁参数**，见 ③ |
| 还是不亮 | 引脚号错 / LED 极性反 / 器件封装选错 → 回去核对第 0 步 |

试完**记得改回来**。

> 这是标准做法：先用一个**确定性的输出**把"下游链路"验证掉，
> 再去查"上游逻辑"。否则引脚问题和分频问题混在一起，没法判断。

### ③ 闪烁参数 → "闪太快看不见"

`DIV = CLK_HZ / (2 * BLINK_HZ)`。

如果 `CLK_HZ` 填的比实际时钟**大很多**，DIV 也跟着变大，
闪烁会**变慢**；填**小很多**则**变快**，快到人眼只看到一片亮（或者看不到变化）。

| 实际情况 | 现象 |
|---|---|
| `CLK_HZ` 填对 | 按 `BLINK_HZ` 闪 |
| `CLK_HZ` 填成实际的 1/10 | 闪得比预期快 10 倍 |
| `CLK_HZ` 填成实际的 10 倍 | 闪得比预期慢 10 倍 |

诊断：把 `BLINK_HZ` 改成 `0.5`（`DIV` 翻倍），看闪烁是否变慢一半。
变了 → 计数器在正常工作，只是频率不对，回来核对 `CLK_HZ`。

> 注意 `BLINK_HZ` 是 `integer` 参数，写 `0.5` 会被截断成 `0`
> 导致除零。要改就改 `CLK_HZ` 或把 `BLINK_HZ` 设为整数。

### ④ 识别不到器件（Auto Connect 失败）

按可能性排序：

1. **USB 线是"只供电"的**（很常见）—— 换一根确定能传数据的
2. **下载器驱动没装** —— Vivado 安装目录下
   `data\xicom\cable_drivers\nt64\` 里有驱动安装程序，跑一遍
   （具体路径随版本略有出入，找不到就在安装目录里搜 `cable_drivers`）
3. 板子没上电 / 电源开关没开
4. 换一个 USB 口（别用前面板扩展口或 hub）

## 附录：复位怎么接（一个需要你拍板的设计选择）

`s00_blinky` 的 `rst_n` 直接连外部按键。这里有个**已知的将就之处**：

按键是**机械**的，直接接到 `rst_n` 上意味着：

- **异步释放**：松手那一刻的边沿和时钟无关，可能让触发器进入亚稳态
- **抖动**：机械触点松手时会抖十几毫秒，`rst_n` 会跳很多次

本仓库的规矩（`AGENTS.md`）是"异步复位、**同步释放**"，
外部按键应当先过 `rtl/common/reset_sync.v`。

**为什么 s00 可以先不处理**：闪灯对复位抖动完全不敏感，
接上去就能跑，先把链条打通更重要。

**上板成功之后的下一步**（三选一，按推荐度排序）：

| 方案 | 做法 | 代价 |
|---|---|---|
| A（推荐） | 新增 `blinky_top.v`，实例化 `reset_sync` + `blinky`，按键接在 `reset_sync` 上 | 多一个模块 + 一个 testbench，`make sim` 要重跑 |
| B | 按键直接接 `rst_n`，接受抖动 | 无。学到的东西少一点，但 s00 够用 |
| C | 干脆不接按键，上电即跑（`rst_n` 在 XDC 里不约束） | ❌ 不行：未约束的端口行为不可预期，工具会报 CRITICAL WARNING 或直接报错，别赌 |

> 方案 A 值得做，因为**后面每一级都要接按键复位**，
> 现在把模式定下来，以后复制粘贴就行。

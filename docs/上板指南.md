# 上板指南 — 从零到 LED 闪烁（Windows / Vivado）

> 目标：把 `s00_blinky` 真正跑到板子上，走通
> **原理图 → XDC → 综合 → 实现 → 比特流 → 下载** 这条链路。
>
> 走通一次之后，后面每个 stage 都照这个流程下板。
>
> ⚠️ 本文里的**引脚号、时钟频率、器件封装**一律是占位符。
> 这些只能从板子的**原理图**（或厂商例程自带的 `.xdc`）里抄，
> **不要靠搜索或记忆猜** —— 引脚错了就是上板不亮，而且很难查。

> ### ✅ 本仓库实采版本：**2020.2**
>
> 2026-10-14 定。判据是"**能不能跑通**"，不是"官方怎么说"。
> 2020.2 官方支持目标是 Win10（发布时 Win11 还不存在），但我们**不打开厂商
> 工程、不用 IP**，社区实测它在 Win11 上可用。
> 为追"官方支持 Win11"的版本绕了一圈（**2025.2 的 web installer 不好用**），
> 代价是几十 GB 下载时间。
>
> **下个会话不需要再讨论版本问题。** 直接往下走：装完 → 两道自检 → 抄引脚。

**这个仓库对 Vivado 版本几乎没有要求。** 因为我们**从不打开厂商的教程工程**——
RTL 全是手写的，没有 IP 核、没有 Block Design；引脚号是从**原理图**上抄的纯文本，
跟教程用的 `.xpr` 一点关系都没有。

> 教程用的是 2020.2，这只在**你去打开教程工程**时才绑住你。我们不打开。

影响版本的只有两件事：

1. **操作系统支持**。2020.2 发布时 Windows 11 还不存在，官方支持目标是 Win10。
   权威来源是 AMD 的
   [Installer and OS Support Information](https://www.amd.com/en/support/adaptive-socs-and-fpgas/installer-info-general.html)
   （JS 渲染页面，得用浏览器打开）。**但"官方不支持"≠"不能用"**——
   我们的判据是能不能跑通。
2. **器件是否还在支持列表里**。Artix-7 属于 7 series，各版本仍在支持范围内，
   免费版也覆盖。AMD 已把 7 系列生命周期延长到 **2040 年**。

### 万一以后要换版本：三条原则

**① 认准免费版**：选 **Vivado ML Standard Edition**（原来叫 WebPACK）。
Artix-7 在免费范围内，**不需要 License 文件**。别选 Enterprise。

**② 不要追最新**。新版本的更新几乎全是给 Versal 等新架构的，
对一棵 Artix-7 的闪灯设计收益为零，却要承担新版本的 bug 风险。
**器件本身不会被砍**——要防的是**新版本的回归 bug**。

**③ ⚠️ 安装时务必勾上 `7 series` / `Artix-7`。**
安装器会让你勾选器件族。漏勾的话装完在 Parts 里搜不到 `xc7a100t`——
社区里就有 [2025.2 只装了 Spartan-7、看不到 Artix-7](https://adaptivesupport.amd.com/s/question/0D5Pd00001MlsTLKAZ/hello-i-have-downloaded-vivado-20252-for-linux-with-support-for-7series-after-installation-in-ubuntu-24-vivado-can-see-only-spartan7-devices-and-no-artix7-devices-the-old-vivado-20212-can-see-artix-7?language=en_US) 的实例。

> 只勾需要的器件族还能**减小安装体积**（全量安装是几十 GB 下载、
> 上百 GB 磁盘）。

### 装完第一件事：自检器件

打开 Vivado，在底部的 **Tcl Console** 里敲：

```tcl
get_parts xc7a100t*
```

- 返回一串器件名 → ✅ 器件族装好了
- 报错或返回空 → ❌ 回去用 installer 补装 `7 series`

**这一条必须在建工程之前做掉**，否则你会在"Create Project 里搜不到自己的芯片"
上卡半天，还以为是板子或工程的问题。

### 装完第二件事：确认下载阶段也能认器件

`get_parts` 只验证了**综合**这一侧。下载是另一条独立的器件识别路径，
**两者可能不一致**——社区里出现过新版本在**下载/编程**阶段报
`unsupported part <7 系列器件>` 的报告。

所以第 5 步（下载）里 **Auto Connect 能不能列出器件**，本身就是一次版本验证：

- 列出了器件 → ✅ 这个版本可以长期用下去
- 报 `unsupported part` 之类 → ❌ 这**不是你比特流的问题**，是工具版本对该器件的识别问题，
  换一个更成熟的版本即可，不要在 RTL 和约束上找原因

**这两道自检都过了，就锁定这个版本别再折腾。** 版本更新对这个项目收益为零。

## 第 0 步：板级引脚（✅ 2026-10-14 已全部查定）

**来源：厂商官方《达芬奇Pro开发板IO引脚分配表》 + 核心板晶振丝印。**
该表是权威资料，比翻原理图可靠。下表是**本仓库实际使用**的信号子集。

| 用途 | RTL 端口 | 板子网络名 | 管脚 | 备注 |
|---|---|---|---|---|
| 时钟 | `clk` | `sys_clk` | **R4** | **50 MHz**（晶振实测确认） |
| 复位 | `rst_n` | `sys_rst_n` | **U7** | 表中标注「**低有效**」= 与 `rst_n` 一致，不用取反 |
| LED0 | `led` | `led[0]` | **V9** | s00 只用这一个 |
| LED1–3 | —— | `led[1..3]` | Y8 / Y7 / W7 | 以后要用再约束 |

对应的约束已经落在 `s00_blinky/constr/blinky.xdc`，**不需要再查任何资料**。

### 时钟 50 MHz 的连锁影响（已核算）

`blinky.v` 的默认值就是 `CLK_HZ = 50_000_000`，**RTL 无需改动**。展开算一遍：

| 量 | 值 |
|---|---|
| `DIV = CLK_HZ / (2 × BLINK_HZ)` | 25,000,000 |
| `CNT_W = $clog2(DIV)` | **25 位**（2²⁵ = 33.5 M ≥ 25 M，装得下） |
| LED 半周期 | 25,000,000 / 50,000,000 = 0.5 s |
| **完整周期** | **1.000 Hz** |
| `create_clock -period` | **20.000 ns** |

> 上板后**预期行为**：LED 以约 1 Hz 闪（亮 0.5 s、灭 0.5 s），复位期间灭。
> 对不上就按下面的「排障」走。

### 仍然没有：器件封装

引脚表不写器件型号。**必须从 Vivado 的 Parts 列表里挑和板子完全一致的那一项**。

> ⚠️ **器件封装最容易出错也最致命**。同为 XC7A100T，
> `fgg484` 和 `csg324` 的引脚编号**完全不同**。
> 型号选错 → 引脚约束全部对不上 → 要么报错，要么"下载成功但灯不亮"。
> 板子丝印 / 用户手册首页能查到封装。

### 关于 LED 极性和 IOSTANDARD（这两个不必纠结）

引脚表里都没有，但**都不影响能不能点亮**：

- **LED 极性**只影响相位。低电平点亮时 `led_r=0` 灯亮，照样是 1 Hz 闪烁。
- **IOSTANDARD** 先填最常用的 `LVCMOS33`。**写错了 Vivado 会立刻报错**
  （"LVCMOS33 对这个 bank 不合法"），一步就能改对。

> 这就是为什么它俩可以先填、**引脚号却必须查准**：
> 引脚号写错是**静默失败**（下载成功但不亮，极难反查），
> 电平标准写错是**立即报错**。前者没有安全网，后者有。

## 第 1 步：建 Vivado 工程

**工程目录必须建在仓库外面。**

```
D:\vivado_prj\s00_blinky\     ← 工程建这里
D:\fpga-lab\                  ← git 仓库在这里
```

为什么要这样：Vivado 的中间文件动辄几 GB 且每次综合都在变。
工程建在仓库里，`git add -A` 一不留神就把几 GB 扫进去了，
而**已经提交过的东西 `.gitignore` 再也管不住**。
建在外面，git 在物理上就看不到它。
（详见 [同步指南.md](同步指南.md) 的「坑 2」）

### 操作

1. Vivado → **Create Project**
2. **Project Name**
   - Project name: `s00_blinky`
   - Project location: `D:/vivado_prj` ← **仓库外**
   - ✅ 勾上 Create project subdirectory
3. **Project Type** → 选 **RTL Project**
   - ❌ **不要**勾 "Do not specify sources at this time"
4. **Add Sources**
   - Add Files → `D:\fpga-lab\s00_blinky\rtl\blinky.v`
   - ❌ **不要**勾 "Copy sources into project"
   - ✅ 勾 "Scan and add RTL include files"
5. **Add Constraints**
   - Add Files → `D:\fpga-lab\s00_blinky\constr\blinky.xdc`
   - ❌ **不要**勾 "Copy constraints files into project"
6. **Default Part**
   - 搜 `xc7a100t`，选**和第 0 步完全一致**的封装/速度/温度等级
7. Finish

> **"不要勾 Copy sources into project" 的理由**：
> 勾了 Vivado 会把源文件**复制一份**到工程目录里。
> 之后你在仓库里改 RTL、重新综合 —— 综合的还是那份旧的副本，
> 于是出现"改了代码但不生效"的诡异现象，能查半天。
> 不勾 = 工程直接引用仓库里的文件，改完立刻生效。

## 第 2 步：XDC 约束（✅ 已填好，只需确认）

`s00_blinky/constr/blinky.xdc` **已经填完了**，第 0 步的数都在里面：

```tcl
set_property -dict {PACKAGE_PIN R4  IOSTANDARD LVCMOS33} [get_ports clk]
create_clock -period 20.000 -name sys_clk [get_ports clk]
set_property -dict {PACKAGE_PIN U7  IOSTANDARD LVCMOS33} [get_ports rst_n]
set_property -dict {PACKAGE_PIN V9  IOSTANDARD LVCMOS33} [get_ports led]
```

**建工程时把它加进去就行，不需要改任何东西。** 下面两条不用做，留着是因为
以后换 stage 会用到：

- 工程是**按路径引用**这个文件的，所以将来改了它**不需要**在 Vivado 里
  重新添加约束，直接重新 Run Synthesis 就生效
- `blinky.v` 里 `CLK_HZ` 默认值已经是 `50_000_000`，**和时钟一致，无需改动**

**为什么直接改源码而不是在 Vivado 里改**：改源码会进 git，有记录、
可复现、我这边能看见；在 Vivado 界面里改只存在工程文件里，
换台机器就丢，而且出问题时无从对照。

（Tcl 方式也行：`synth_design -generic CLK_HZ=50000000`。
GUI 流程下改源码更省事。）

## 第 3 步：综合

- **Run Synthesis**（左侧 Flow Navigator）
- 等它跑完，看打开的 Synthesis Design 有没有问题
- 结束时会弹窗，选 **Open Synthesized Design**

**要看的**：Tcl Console 里的 `CRITICAL WARNING`。最常见的是**端口名对不上**：

| 现象（消息文本） | 含义 |
|---|---|
| `'set_property' expects at least one object` | XDC 里 `get_ports xxx` 没匹配到任何端口 |
| 提到 `No ports matched` / `get_ports` 找不到对象 | XDC 里的端口名和 RTL 里的不一致 |

> 这类错误的根因几乎总是同一个：`get_ports` 后面写的名字
> 必须是**顶层模块的端口名**（这里是 `clk` / `rst_n` / `led`），
> 不是网络标号、不是引脚号。
>
> （具体错误码随 Vivado 版本会变，按**消息文本**搜，别按错误码搜。）

## 第 4 步：实现 + 生成比特流

- **Run Implementation** → **Open Implemented Design**
- 看 **Timing Summary**：`WNS`（Worst Negative Slack）必须 **≥ 0**
- **Generate Bitstream**

> `s00_blinky` 是纯粹的分频计数器，时序**不可能**不收敛。
> 如果这里出现违例，一定是约束填错了（多半是 `create_clock` 周期写反了），
> 不要去找 RTL 的问题。

## 第 5 步：下载

1. 板子**上电**，USB 线接下载口
2. Flow Navigator → **Open Hardware Manager**
3. **Open Target** → **Auto Connect**
4. 出现 `xc7a100t_0` 之类的器件图标 = 识别成功
5. 右键器件 → **Program Device** → 选刚生成的 `.bit`

下载完成后应该看到 LED 以设定频率闪烁。

## 第 6 步：把日志带回 Mac（**这步别省**）

### 为什么必须有这一步

仓库的铁律之一是「**报告要给出证据**」。上板跑通了，但如果仓库里没有
综合日志和时序/资源报告，那"跑通了"就只是一句话：

- 没有时序报告 → 不知道 WNS 是多少，有没有隐性违例
- 没有资源报告 → 后面 stage（混频器 / FIR）做资源规划时**没有基线**
- 没有综合日志 → 工具报过的 CRITICAL WARNING 全丢了

而且 **Mac 这边看不到你 Vivado 里的任何东西。文件是唯一的通道。**

### 拷什么、放哪

工程在仓库**外面**，所以要手动拷。目标目录：

```
logs/s00_blinky/
├── synth_runme.log      ← 综合日志
├── impl_runme.log       ← 实现日志
├── timing_summary.rpt   ← 时序摘要（WNS / TNS）
├── utilization.rpt      ← 资源用量（LUT / FF / BRAM / DSP）
└── drc.rpt              ← 设计规则检查
```

**只拷文本。** 不要 `.dcp` / `.bit` / `.runs/` 目录 —— 那些是几百 MB 到几 GB
的中间产物，`make hooks` 装的守卫会拒绝它们。

#### ① 综合 / 实现日志：从工程目录拷出来

```
D:\vivado_prj\s00_blinky\s00_blinky.runs\synth_1\runme.log
D:\vivado_prj\s00_blinky\s00_blinky.runs\impl_1\runme.log
```

⚠️ **必须拷出来，不能在原地 `git add`** —— 这两个文件在 `*.runs/` 目录里，
而 `.gitignore` 忽略整个 `*.runs/`。

> 路径里的 `s00_blinky` 是你的**工程名**，`synth_1` / `impl_1` 是 **run 名**。
> 建工程时名字取得不一样，路径就跟着不一样。

#### ② 三条报告 —— 优先走「现成的文件」，而不是 Tcl Console

**首选：`impl_1` 目录里 Vivado 已经自动写好了一批 `.rpt`。**

实现完成后，去工程目录里翻：

```
<你的工程目录>\s00_blinky.runs\impl_1\
```

里面会有类似这样的文件，**直接拷到 `logs/s00_blinky/` 就行**：

```
<顶层名>_timing_summary_routed.rpt      ← 时序摘要（WNS / TNS）
<顶层名>_utilization_placed.rpt         ← 资源用量
<顶层名>_drc_routed.rpt                 ← 设计规则检查
<顶层名>_clock_utilization_routed.rpt   ← 时钟资源
```

> 为什么推荐这条路：**它不需要 Tcl Console 能用。**
> Tcl Console 在 run 运行中、或有模态弹窗时会**被锁住、打不进字**
> —— 实测踩过。而报告本来就已经在磁盘上了，没必要绕一圈。

**备选：Tcl Console**（如果上面那个目录里没有你想要的报告）

```tcl
open_run impl_1
report_timing_summary -file D:/fpga-lab/logs/s00_blinky/timing_summary.rpt
report_utilization    -file D:/fpga-lab/logs/s00_blinky/utilization.rpt
report_drc            -file D:/fpga-lab/logs/s00_blinky/drc.rpt
```

Windows 路径用**正斜杠** `/`（Vivado 也认反斜杠，但别在 Tcl 里用 ——
反斜杠是转义字符）。

⚠️ **目标目录必须先存在。** `-file` 不会替你创建目录，目录不存在时命令会失败。
本仓库已经在版本库里放好了 `logs/s00_blinky/`，`git pull` 之后它就在。

> **Tcl Console 打不进字怎么办**：先确认 ① Flow Navigator 里没有 run 在跑
> （进度条在转）② 没有没关掉的弹窗。这两个都会锁住 console。
> 焦点不对的话，鼠标点一下输入区。实在不行 `Window → Tcl Console` 重开。

## 排障：灯不闪怎么办

按**从后往前**的顺序二分，别跳步。

### ① 先确认比特流真的下进去了

- Hardware Manager 里器件有没有出现？没有 → 见下面「识别不到器件」
- Program 之后有没有报错？
- 板子上有没有 `DONE` 指示灯亮？亮了至少说明配置成功

### ② 用"常亮/常灭"排除引脚和极性（**最有效的一招**）

把 `blinky.v` 里最后一行的

```verilog
assign led = led_r;
```

临时改成

```verilog
assign led = 1'b1;    // 低电平点亮的板子改成 1'b0
```

重新综合下载：

| 结果 | 结论 |
|---|---|
| **亮了** | 引脚对、下载链路对 → 问题在**闪烁参数**，见 ③ |
| 还是不亮 | 引脚号错 / LED 极性反 / 器件封装选错 → 回去核对第 0 步 |

试完**记得改回来**。

> 这是标准做法：先用一个**确定性的输出**把"下游链路"验证掉，
> 再去查"上游逻辑"。否则引脚问题和分频问题混在一起，没法判断。

### ③ 闪烁参数 → "闪太快看不见"

`DIV = CLK_HZ / (2 * BLINK_HZ)`。

如果 `CLK_HZ` 填的比实际时钟**大很多**，DIV 也跟着变大，
闪烁会**变慢**；填**小很多**则**变快**，快到人眼只看到一片亮（或者看不到变化）。

| 实际情况 | 现象 |
|---|---|
| `CLK_HZ` 填对 | 按 `BLINK_HZ` 闪 |
| `CLK_HZ` 填成实际的 1/10 | 闪得比预期快 10 倍 |
| `CLK_HZ` 填成实际的 10 倍 | 闪得比预期慢 10 倍 |

诊断：把 `BLINK_HZ` 改成 `0.5`（`DIV` 翻倍），看闪烁是否变慢一半。
变了 → 计数器在正常工作，只是频率不对，回来核对 `CLK_HZ`。

> 注意 `BLINK_HZ` 是 `integer` 参数，写 `0.5` 会被截断成 `0`
> 导致除零。要改就改 `CLK_HZ` 或把 `BLINK_HZ` 设为整数。

### ④ 识别不到器件（Auto Connect 失败）

按可能性排序：

1. **USB 线是"只供电"的**（很常见）—— 换一根确定能传数据的
2. **下载器驱动没装** —— Vivado 安装目录下
   `data\xicom\cable_drivers\nt64\` 里有驱动安装程序，跑一遍
   （具体路径随版本略有出入，找不到就在安装目录里搜 `cable_drivers`）
3. 板子没上电 / 电源开关没开
4. 换一个 USB 口（别用前面板扩展口或 hub）

## 附录：复位怎么接（一个需要你拍板的设计选择）

`s00_blinky` 的 `rst_n` 直接连外部按键。这里有个**已知的将就之处**：

按键是**机械**的，直接接到 `rst_n` 上意味着：

- **异步释放**：松手那一刻的边沿和时钟无关，可能让触发器进入亚稳态
- **抖动**：机械触点松手时会抖十几毫秒，`rst_n` 会跳很多次

本仓库的规矩（`AGENTS.md`）是"异步复位、**同步释放**"，
外部按键应当先过 `rtl/common/reset_sync.v`。

**为什么 s00 可以先不处理**：闪灯对复位抖动完全不敏感，
接上去就能跑，先把链条打通更重要。

**上板成功之后的下一步**（三选一，按推荐度排序）：

| 方案 | 做法 | 代价 |
|---|---|---|
| A（推荐） | 新增 `blinky_top.v`，实例化 `reset_sync` + `blinky`，按键接在 `reset_sync` 上 | 多一个模块 + 一个 testbench，`make sim` 要重跑 |
| B | 按键直接接 `rst_n`，接受抖动 | 无。学到的东西少一点，但 s00 够用 |
| C | 干脆不接按键，上电即跑（`rst_n` 在 XDC 里不约束） | ❌ 不行：未约束的端口行为不可预期，工具会报 CRITICAL WARNING 或直接报错，别赌 |

> 方案 A 值得做，因为**后面每一级都要接按键复位**，
> 现在把模式定下来，以后复制粘贴就行。

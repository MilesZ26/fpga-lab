# 上板对账表：`fir_top` 的冲激响应期望值

> **用途**：上板用 ILA 抓 `fir_dbg` 时，逐点对账用的表。
> 以前这一步要"拿 coef.mem 乘 2047/32768 手算"，现在直接查这里。
>
> **真值来源**：`coef.mem`（Q1.15）+ 下面这条公式，和 RTL 的运算**逐位一致**：
>
> ```
> h[k] = floor( ( coef[k] * 2047 + 2^14 ) / 2^15 )
> ```
>
> 为什么是 `floor(... + 2^14)` 而不是"四舍五入"：`fir.v` 的 `ROUND=1` 是
> "加半个 LSB 再**算术右移**"，算术右移等价于对负数向 −∞ 取整。
> 所以严格说它叫 **round-half-up on the shifted value / floor toward −∞**，
> 在正的半边看起来就是四舍五入，在负的半边在 `.5` 这个点上和"远离零舍入"差 1。
> 用 `floor` 写才和 RTL 一位不差。

## 板上怎么判"过了"

| 检查 | 期望 | 说明 |
|---|---|---|
| 冲激间隔 | **1024** 点 | `IMP_PERIOD`，50 MHz 下 20.48 µs |
| 响应长度 | **47** 点，之后回 0 | 第 48 点起全是 0（低通 FIR 的有限长记忆） |
| 峰值 | **613** @ k=23 | 单位置单点，别拿 `==613` 当触发（s01 的坑） |
| 两端 | **1** @ k=0 和 k=46 | 非零但很小 —— 容易被误当成"没起来" |
| 对称性 | `h[23+m] == h[23-m]`，23 对全部相等 | **线性相位的直接证据**，一眼能看出来 |
| 直流增益 | 输入若换成常数 2047，稳态输出 = 2047 | 系数和 = 32768 = 2^15 的直接后果 |
| 符号 | 第 4、5、6 个点起是**负**的 | ILA 里 `fir_dbg` 要设成 **signed（有符号）显示**，否则 -117 会显示成 8075 |

> **`h[3] = 0` 和 `h[13] = 0` 不是 bug**：`coef[3]` / `coef[13]` 量化后本身就是 0
> （窗函数法 sinc 在这个位置小于半个 LSB）。见 [`README.md`](README.md)。

## 和 ILA 触发的关系

- 触发条件用 `imp_dbg == 1`，那么**触发点那一拍就是 `x[n]`**；
  由于 `fir.v` 是 4 级流水，`fir_dbg` 上的 `h[0]` 出现在**触发点之后第 4 个采样点**。
- 所以 ILA 窗口里：触发点 + 4 → `h[0]`，触发点 + 4 + 23 = **触发点后第 27 个点** → 峰值 613。
- 采样深度 8192、时钟 50 MHz → 窗口 163.84 µs → 能装 **8 个**完整冲激（含中间的空档）。

## 重新生成

系数变了这张表就过期。生成方式（Mac 侧，`python3` 可用时）：

```sh
python3 - <<'PY'
c = [int(l, 16) for l in open('s03_fir/lut/coef.mem') if l.strip()]
c = [v - 65536 if v >= 32768 else v for v in c]
h = [ (v * 2047 + 16384) // 32768 for v in c ]
print(', '.join(map(str, h)))
PY
```

> 注意 `//` 在 Python 里对负数就是 floor，正好和 RTL 的算术右移一致 ——
> 别改成 `int(...)` 或 `round()`，那会在负半边的 `.5` 点上差 1。

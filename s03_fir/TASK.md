> 基带数据通路的第三个零件。NCO 产生本振、混频器搬频谱，FIR 负责**留下想要的频带**。
> DUC（s05）里它在混频之后、插值之前；DDC（s06）里顺序反过来。
>
> **这是第一个"真正的硬骨头"**：卷积、系数设计、对称优化、流水线、位宽预算
> 全都压在一个模块里。s01/s02 的"组合乘加 + 1 拍寄存器"那套写法到这里不够用了。

## 目标

一个参数化的对称抽头 FIR 低通：

```
                 ┌──────────────────────────────┐
  x_in ─────────►│ x_r → dly[] → 预加 → 乘 → 加树 │─────────► y_out
                 │        (N taps, 对称折叠)      │
                 └──────────────────────────────┘
```

| 参数 | 含义 | 默认 |
|---|---|---|
| `IW` | 输入位宽（补码） | 12 |
| `CW` | 系数位宽（补码，Q1.CW-1） | 16 |
| `N` | 抽头数 | 47 |
| `OW` | 输出位宽（补码） | `IW+1` = 13 |
| `SHIFT` | 输出右移位数（增益归一化） | `CW-1` = 15 |
| `ROUND` | 1 = 四舍五入；0 = 截断 | 1 |
| `COEF_FILE` | 系数文件名（目录由 `FIR_COEFDIR` 给） | `"coef.mem"` |

| 端口 | 方向 | 含义 |
|---|---|---|
| `clk` / `rst_n` | in | 时钟 / 低有效异步复位 |
| `x_in` | in | 输入样本（补码） |
| `y_out` | out | 滤波输出（补码，**晚 4 拍**） |

运算：

```
y[n] = ( sum_{k=0}^{N-1} c[k] * x[n-k] ) >>> SHIFT
```

## 写之前要决定的四件事（已决定 + 理由）

### ① 系数从哪来：脚本设计 + `.mem`，不用 IP

Vivado 综合不了浮点设计，系数必须是常量。继续用 s01 的做法：
Python 离线设计 → Q1.15 量化 → `lut/coef.mem` → RTL 里 `$readmemh`。
好处是**仿真和综合读同一份文件**，不会"仿真对、上板错"。

系数设计用**窗函数法**（理想低通 sinc × Hamming 窗），不是等波纹最优：
没有迭代、没有优化器，每个数字都能手算核对。代价是同样抽头数下过渡带更宽。

| 指标 | 默认设计 |
|---|---|
| 抽头数 | 47（奇数 → 群延迟 = 23 个采样，整数拍，测试好对账） |
| 归一化截止 | 0.15（Fs = 50 MHz 时是 7.5 MHz） |
| 窗 | Hamming |
| 系数格式 | Q1.15，16 位补码 |
| 系数和 | **32768 = 2^15**（直流增益精确为 1.0） |
| 最大 / 最小系数 | +9810（中心）/ −1867 |
| 通带 [0, 0.10] 纹波 | **0.037 dB** |
| 阻带 [0.20, 0.5] 衰减 | **55.7 dB** |
| 群延迟 | 23 个采样 |

> **为什么系数和是 2^15 而不是 2^15−1？**
> Q1.15 里 `1.0` 对应 `2^15 = 32768`。低通的直流增益是 `sum(h) = 1`，
> 所以量化后让和精确等于 32768，常数输入经过滤波器后**逐位不变**。
> 这比"和 = 32767（差 1 LSB）"干净得多，测试可以写成严格相等。
> 量化误差全部塞给中心抽头吸收，对称性不变（奇数抽头只动中心）。

### ② 为什么对称抽头：线性相位 + 省一半乘法器

窗函数法设计出来的低通天然满足 `c[k] = c[N-1-k]`，这叫**线性相位**：
所有频率的群延迟相同，波形不会被滤"歪"。

对称还白送一个结构优化：

```
y[n] = sum_{i=0}^{H-1} c[i] * ( x[n-i] + x[n-(N-1-i)] )   (+ 中心抽头)
```

**先加后乘**。加法器比乘法器便宜得多：N=47 时乘法器从 47 降到 **24**
（23 对 + 1 个中心）。Artix-7 上 DSP48 是紧俏资源，这一下省掉一半。

代价：多了一级预加器，关键路径变成"预加 + 乘"，但 DSP48 内部本来就有
pre-adder，所以通常还是 1 个 DSP 干一对。

### ③ 位宽：全精度算完再截

| 量 | 位宽 | 为什么 |
|---|---|---|
| 预加和 | `PA_W = IW+1 = 13` | 两个 12 位有符号数相加可能到 13 位 |
| 单个乘积 | `PROD_W = PA_W+CW = 29` | 13 位有符号 × 16 位有符号的全精度 |
| 乘积和 | `SUM_W = PROD_W + ceil(log2(NP)) + 1 = 35` | 24 个乘积相加要长 5 位；再留 1 位给舍入 |
| 最终和 | `FINAL_W = SUM_W+1 = 36` | 加半个 LSB 可能把最大正值顶出 SUM_W |
| 输出 | `OW = IW+1 = 13` | 单位增益理论上 12 位够；多 1 位留余量 |

**先全精度、最后才截**。提前截中间结果省不下 DSP，只会白丢精度，
而且会让"哪一位代表什么"变得很难查。

`OW=IW+1` 是保守选择：这套系数和 = 32768，满幅 ±2048 输入理论上正好
输出 ±2048，12 位就够；多 1 位是为了以后换一组增益 > 1 的系数时不用改接口，
也避免舍入在边界上多 1 LSB 就溢出。**饱和逻辑用 `tb_fir.v` 里 OW=8 的
实例单独验**，不靠主配置去撞边界。

### ④ 流水线：4 级，每级都打拍

| 级 | 做什么 | 位宽 |
|---|---|---|
| 1 | 输入寄存 + 采样延迟线 `x_r / dly[]` | 12 |
| 2 | 对称预加 + 乘法 → `p_reg[]` | 29 |
| 3 | 4 组部分和 → `gsum[]`（每组最多 6 个乘积） | 35 |
| 4 | 4 组相加 + 舍入 + 右移 + 饱和 → `y_out` | 13 |

为什么加法树要分组：24 个 29 位乘积如果在一个周期里做 5 层加法，50 MHz
也许能过，但余量会被吃掉。分成"组内 3 层 + 组间 2 层"后，每级只有 3 层左右
加法，时序余量大得多。代价是延迟 4 拍，FIR 在数据通路里，这完全可以接受。

**延迟 = 4 拍**（输入在时钟沿被采样，第 4 个时钟沿出 `y_out`）。
TB 的约定是：下降沿驱动 `x_in`，同一个下降沿读 `y_out`，第 k 个下降沿的输入
对应第 k+4 个下降沿的输出。

## 验收标准

- [x] 复位期间输出为 0；**运行中途异步复位**不等时钟沿立刻清零
- [x] **延迟 4 拍**：第 3 拍输出仍为 0，第 4 拍才出现 h[0]
- [x] **冲激响应 = 系数表**：47 个抽头逐个和 `round(2047*c[k]/2^15)` 比对；
      中心抽头 = **613**，两端 = 1
- [x] **线性相位**：`h[k] == h[N-1-k]` 逐位相等（47 个点全成立）
- [x] **直流增益精确为 1**：±1000、+2047、−2048 的稳态输出逐位恢复
- [x] **参考向量回放**：4 个场景 × 512 样本逐位一致
      （impulse / step / tones / random，Python 任意精度模型生成）
- [x] **舍入 / 截断可区分**：5 抽头实例上 `x=±2` 打在系数 8192 上 = 半个 LSB，
      `ROUND=1` 得 1/0，`ROUND=0` 得 0/−1；主滤波器随机场景里两者 >50 拍不同
- [x] **饱和而不是回绕**：`OW=8` 实例上 +2047→+127、−2048→−128、100→100
- [x] **参数真的起作用**：N=5/47、OW=8/13、IW=8/12 都测到
- [x] **两张表同时加载**：`tb_table_binding.v` 同时例化 s01 的 nco 和 s03 的 fir，
      证明 `NCO_LUTDIR` / `FIR_COEFDIR` 各自指对目录
- [x] `make sim` 全绿、`make lint` 无警告
- [x] **上板 + ILA**（2026-10-18 完成）：8 个冲激 / 47 点响应 / 613 / 1 / 全对称，
      四颗 LED 1 Hz 闪。报告在 `logs/s03_fir/`。

### 反向验证（仓库规矩 3）：4 处改坏，全部变红

| 改坏的地方 | `tb_fir.v` 的实际反应 |
|---|---|
| F1 系数下标 `coef[gi]` → `coef[gi+1]` | **12 条 FAIL**：冲激响应 42 个点错、4 条直流、4 个向量场景、tie、IW=8 |
| F2 关掉四舍五入（`ROUND == 2`） | **10 条 FAIL**：4 个向量场景、25 个冲激点、中心 612、tie 正/负、ROUND 没生效 |
| F3 饱和改成回绕 | **2 条 FAIL**：正好是 OW=8 的正/负溢出检查（主配置不饱和，抓不到 —— 正常） |
| F4 中心抽头 `dly[HALF-1]` → `dly[HALF-2]` | **11 条 FAIL**：中心抽头 0、对称性 2 点、4 个向量场景、tie 负 |

> F3 只有 2 条，正好说明"为什么主配置之外还要一个 OW=8 的实例"：
> 主配置离饱和边界很远，饱和逻辑改坏了它一点感觉都没有。
> **两个 TB 的判据强度不一样，不是重复劳动。**

只改一个不重新生成，仿真要么失败得莫名其妙，要么"回放全绿但测的是旧滤波器"。

## 上板（✅ 2026-10-18 实测通过）

板级顶层 `fir_top.v` 不复用 NCO，而是每 `IMP_PERIOD=1024` 拍发一个
**单点冲激**（幅度 2047）。FIR 输出就是冲激响应，ILA 上直接和系数表对账：

- 周期 **1024 个采样点 = 20.48 µs**，8192 点窗口里能看到 8 个冲激 → **实测 8 个** ✅
- 每个冲激后 47 个点：中心 **613**、两端 **1**、关于第 23 点对称 → **逐点对上** ✅
- 四颗 LED 都接 1 Hz 心跳 → **四颗都闪** ✅

**实测资源 / 时序**（`logs/s03_fir/`）：

| | 综合后（纯设计） | 布局后（含 ILA） |
|---|---|---|
| LUT / Reg | 942 / 1400 | 1913 / 3242 |
| BRAM / DSP | 0 / **21** | 3.5 / 21 |
| WNS | — | **+10.273 ns** |

> **DSP 是 21 不是预估的 24**：`coef[3]` / `coef[13]` 量化后为 0，两个乘法器被删；
> 差的那 1 个原因未坐实（可能是小常数乘走移位加法）。不影响功能。

详细步骤、`FIR_COEFDIR` 配法、ILA 注意事项见 `constr/fir.xdc`；
47 点对账表见 [`lut/expected_h.md`](lut/expected_h.md)。

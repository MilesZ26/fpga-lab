# Stage 1 — NCO（数控振荡器）

> 基带数据通路的第一个零件。NCO 是 DUC/DDC 的本振来源：
> 把相位"算"出来，再查表变成正弦/余弦样本。

## 目标

一个参数化的 NCO：**相位累加器 + 查表**，同时输出正弦和余弦。

## 参数 / 端口

| 参数 | 含义 |
|---|---|
| `CLK_HZ` | 输入时钟频率（仿真时调小） |
| `FREQ_HZ` | 期望的输出频率 |
| `PHASE_W` | 相位累加器位宽（如 16 / 24 / 32） |
| `LUT_AW` | 查表地址位宽，表深 = `2**LUT_AW` |
| `AW` | 输出幅度位宽（如 12 / 16） |

| 端口 | 含义 |
|---|---|
| `clk` | 时钟 |
| `rst_n` | 低有效复位 |
| `sin_out` | 正弦输出 |
| `cos_out` | 余弦输出 |

## 验收标准

> 状态（2026-10-15）：实现在 `rtl/nco.v`，验收在 `tb/tb_nco.v`（21 个检查点）。
> 端口名实际用的是 `fsin_o` / `fcos_o`（不是表里的 `sin_out` / `cos_out`）。

- [x] 复位后相位累加器 = 0，两个输出都稳定
      —— 顺带覆盖了**运行中途异步复位**（不等时钟沿就清零）
- [x] **周期正确**：输出一个完整的正弦周期 = `2**PHASE_W / FTW` 个时钟
      —— 黑盒测两个 sin 峰值间隔：`PHASE_W=16, FTW=1024` → 实测 64 拍
- [x] **幅度恒定**：`sin_out² + cos_out²` 在容差范围内是常数
      —— 单边最大偏差实测 **2591**，量化理论上界 2895，判据取 4096
      （容差怎么来的写在 TB 注释里，别改成"必须完全相等"）
- [x] **频率误差可解释**：实际频率和 `FREQ_HZ` 的偏差，要能对上
      `FTW` 取整引入的量化误差，而不是"差不多就行"
      —— TB 里有两组：`FTW` 恰好整除（误差 0）与 `FTW` 除不尽
      （截断 → 系统性偏低 ≤ 1 个 LSB ≈ 4.6 ppm）。**注意**：4.6 ppm 这个量级
      用"数 100 个周期"是**测不出来**的（分辨率只有 ~130 ppm），所以那条判的是算术
- [x] **参数真的起作用**：至少换一组 `PHASE_W` / `LUT_AW` 再跑一次
      —— `PHASE_W` 换到 24 跑了两组（含只换位宽、频率不变那组）；
      `LUT_AW`/`AW` 暂时没做成参数（12 位地址、4096 深、12 位输出写死）
- [x] 复位行为覆盖到
- [x] `make sim` 全绿（6/6、70 个检查点），`make lint` 无警告
      —— 补上 `` `timescale 1ns/1ps `` 之后警告消失

**反向验证（仓库规矩 3）**：故意改坏 3 处，测试都必须变红 —— 实测
地址移位改错 → 7 条 FAIL、删掉输出复位 → 2 条 FAIL、sin/cos 查表互换 → 3 条 FAIL；
恢复后与备份逐字节一致、重新全绿。

## 写之前要决定的三件事

**① 表数据从哪来**（最重要）

仿真里可以偷懒现算：

```verilog
initial for (i = 0; i < 2**LUT_AW; i = i + 1)
    rom[i] = $rtoi($sin(2.0 * 3.14159265 * i / (2.0**LUT_AW)) * 32767.0);
```

**但 Vivado 综合不了 `$sin`**，综合要求表里的值是常量。所以要么用一个脚本
生成常量表文件，要么用 Vivado 的 ROM IP。**先想清楚再动手**，因为它影响文件结构。

> ✅ **已定（2026-10-15）：脚本生成常量表，不用 ROM IP。**
> 表在 `s01_nco/lut/`：`sin.mem` / `cos.mem`，各 4096 行 × 12 位**二进制补码**，
> `$readmemh` 读入（仿真和综合同一份数据）。生成器 `scripts/gen_lut.py`
> （`make lut` / `make lut-check`），格式与路径坑见 `s01_nco/lut/README.md`，
> 数据本身的校验在 `s01_nco/tb/tb_lut.v`（12 个检查点，已并入 `make sim`）。
> **RTL 里读表照抄 `tb_lut.v` 的 `NCO_LUTDIR` 写法**，否则 vvp 在 `build/` 里跑会读不到
> 而且不报错（表里全是 x）。

**② 有符号还是无符号**

sin/cos 天然是负的。用 `signed` 直接表达，还是加一个直流偏置变成无符号？
两种都有人用。`signed` 更贴近后面的复数混频。

> ✅ **已定：有符号补码，幅值 ±2047（不用满 -2048）。** 理由见
> `s01_nco/lut/README.md`：混频是复数乘法，有符号更顺；对称量化保证表里无直流。

**③ 要不要做象限对称**

只用 1/4 张表 + 符号翻转，可以把 ROM 缩小 4 倍。**第一版建议不做**——先把
基本的跑通，这个留到要去面积/资源的时候再回头优化。

## 提示

- **相位累加器的结构跟 `blinky` 的计数器几乎一样**，只是把"数到 DIV 归零"
  换成"一直加、自然溢出回绕"。溢出就是相位绕了一整圈，这是 NCO 的巧妙之处。
- 频率控制字：`FTW = round(FREQ_HZ * 2**PHASE_W / CLK_HZ)`
- 频率分辨率 = `CLK_HZ / 2**PHASE_W`。**FTW 只能取整**，所以实际频率一定有点偏，
  这个偏差要能被算出来、也要在测试里说清楚。
- 查表地址 = 相位的**高 `LUT_AW` 位**。低位被丢掉，这叫**相位截断**，
  会引入杂散——第一版不管它，但知道有这么回事。
  （简单起见可以让 `LUT_AW = PHASE_W`，先不截断。）
- **仿真参数选能整除的**，别让量化误差干扰判据。例如：

  | 参数 | 值 |
  |---|---|
  | `CLK_HZ` | 1024 |
  | `FREQ_HZ` | 16 |
  | `PHASE_W` | 16 |
  | 算出来 `FTW` | `16 * 65536 / 1024 = 1024` |
  | 输出周期 | `65536 / 1024 = 64` 拍 |

  刚好整除，周期是整数拍，测试好写。

- **不要在 RTL 里实时算 `$sin`** —— 那是软件思维，而且不可综合。
